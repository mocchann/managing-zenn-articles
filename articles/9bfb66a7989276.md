## Blacksmithとは

簡単にいうとGitHub Actionsで使う高速なRunnerやAction、Storageを提供してくれるサービスです。

https://docs.blacksmith.sh/blacksmith-runners/overview

ドキュメントも整えられていて良い感じです。

GitHub Actionsより2倍高速でコストは75%になると謳われています。

## Blacksmithの特徴

### 移行コストが極小

Runnerを変えるだけなら、1行の変更で済みます。

![alt text](</images/9bfb66a7989276/runner_diff.png>)

GitHubと同じイメージから起動することで同じ環境を提供してくれているみたいです。

### Runnerが高機能&低コスト

最新のゲーミングCPU群上で実行、コストもGitHubより低いとあります。

https://docs.blacksmith.sh/blacksmith-runners/overview

※ドキュメントにはGitHubの半額と記載がありますが、GitHub側で価格改定があったため現状半額ではないです。(先ほどの比較表の通り)

金額も以下ドキュメントにまとまっています。

https://www.blacksmith.sh/pricing

### Cacheが4倍高速

BlacksmithではGitHubの4倍高速なキャッシュを謳っています。

仕組みとしては、キャッシュをランナーと同じデータセンターに保存することでネットワークレイテンシーがなくなり、4倍高速化を実現できるようです。

加えてリポジトリ単位で週ごとに25GBのStorageが提供されており、キャッシュヒットの最大化もできると記載されています。

https://docs.blacksmith.sh/blacksmith-caching/dependencies-actions

コードも既存のactions/cacheから変更の必要がないため、開発者としても嬉しい内容ですね。

### Sticky Disksを使えばDocker Buildを高速化

コードを以下のように変更することで、CI実行間でDockerレイヤーを永続化できるようです。

![alt text](</images/9bfb66a7989276/docker_diff.png>)

公式では2~40倍の高速化の報告があったと記載されており、かなりの改善が期待できます。

https://docs.blacksmith.sh/blacksmith-caching/docker-builds

1つ注意点としては、このactionを使うとDockerレイヤーキャッシュの保存先にSticky Disks(永続化ディスク)が使用されるため、$0.50/GB/月の課金が発生します。

Sticky Disksはコストが高いため必要な箇所に絞って利用したり、古いキャッシュは削除したりする等対応が必要かと思われます。

ただ、デフォルトでは7日間未使用のキャッシュは削除されるのと、Sticky Disksを使うことでジョブ間でも同じキャッシュを参照できるため、GitHub Artifactのアップロード・ダウンロードの実装を省けるというメリットもあります。

### ダッシュボードが見やすい

まだ少ししか触っていませんが、ダッシュボードがかなり見やすい印象です。

例えば「この開発者が実行したこのリポジトリのmainブランチのRSpec実行時のERRORを確認したい。」みたいに細かく対象を絞り込みながら確認ができます。

![alt text](</images/9bfb66a7989276/dashboard_run_history.png>)

他にも画像のサイドバーにあるように色々なデータを閲覧できるのですが個人的にはCI実行時のメトリクスが見れるのが面白いなと思いました。

![alt text](</images/9bfb66a7989276/dashboard_metrics.png>)

## 実際に検証してみた

1. Blacksmithに登録

以下からBlacksmithへ登録。

https://www.blacksmith.sh/

2. 検証用のOrganizationを作成

3. OrganizationsにBlacksmithをインストール

4. 比較のために個人開発リポジトリをOrganizationにFork

5. BlacksmithのMigration WizardでRunnerを変更

ボタンをポチポチすれば自動でMigration PRを作成してくれます。

Blacksmithを使いたいリポジトリを選択。

![alt text](</images/9bfb66a7989276/select_repo.png>)

Runnerを選択(デフォルトでは4vcpuになっている、今回はGitHub Actionsと同一条件で比較したかったため2vcpuを選択)

![alt text](</images/9bfb66a7989276/select_runner.png>)

Docker Buildを高速化したい場合は、ここで専用actionを選択(永続化ディスクであるSticky Disksが使われる)

今回のリポジトリではdocker/build-push-actionを未使用だったため差分はありませんでした。

![alt text](</images/9bfb66a7989276/select_docker_builds.png>)

最後に生成するとPRがopenされる

![alt text](</images/9bfb66a7989276/generate_pr.png>)

移行コストが極小なのも良いですね

6. 新規Organizationの制限解除をBlacksmith側に依頼

いざBlacksmithのrunnerでCIを実行しようとしたところCIが実行されませんでした。

Blacksmithのダッシュボードを確認したところ以下エラーメッセージが出ていました。

```
This account requires additional verification. Contact support for help
```

こちらをBlacksmithに問い合わせてみると「セキュリティ対策のため、新規作成されたOrganizationsはデフォルトでブロックされている」とのこと。

そこで、用途や月単位でのジョブ実行時間、ジョブ利用地域などを回答し、支払い方法も登録した上で返答すると無事制限が解除されBlacksmithのRunnerを使ってCIが動作するようになりました。

(また、問い合わせをする際にlinkedinアカウントが必要になったため、別途作成も行いました。)

7. 既存、検証用リポジトリで同CIを実行して差分比較

![alt text](</images/9bfb66a7989276/ci_diff.png>)

というわけで冒頭の検証結果になりました

## まとめ

最後にメリット・デメリットをまとめて終わりにします。

RunnerをBlacksmithに変えるだけでも十分な恩恵が得られるのではないかと思いました！

### メリット

- Runnerコストが下がり、実行速度は高速化する
- Cache StorageもGitHubと互換性があり、コストもかからない、無料枠が増加するためキャッシュヒット率も上昇が期待できる
- Docker Buildを高速化したい場合にSticky Disksを利用可能
- 移行コストが低い、移行サポートもあり
- Blacksmithのダッシュボードが見やすい

### デメリット

- GitHub側の障害だけでなく、Blacksmith側の障害にも影響を受けるようになる
- Sticky Disksはコスト高($0.50/GB/月)のため、利用したいポイントを絞る必要がある
